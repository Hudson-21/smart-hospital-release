## 根路径 403 修复（AuthFilter）
- 用户反馈：重新运行后打开系统显示「403 · 无访问权限，当前角色：病人」。
- 定位依据：Smart Tomcat 访问日志 `10:18:26 GET /hospital → 302`、`GET /hospital/ → 403 872`；响应体样式与 `AuthFilter.forbidden()` 内联页面一致，确认是角色授权拦截，不是 CSRF。
- 原因：请求 `/hospital/` 时 `getRequestURI()` 为 `/hospital/`，剥离 contextPath 后 `path="/"`；`isPublic()` 对 `/` 明确返回 false，`isAllowed()` 中各角色白名单均不含 `/`，default deny 因此返回 403。欢迎页 `login.jsp` 根本没机会被容器解析。
- 附带风险：不能靠「放行 / 交给 welcome-file」修——`login.jsp` 开头会 `session.invalidate()`，已登录用户会被静默登出。
- 修改 `src/com/hospital/AuthFilter.java`：在 path 计算后、isPublic 前增加根路径分支，`path` 为空或 `/` 时，已登录 `sendRedirect(ctx + "/index.jsp")`，未登录 `sendRedirect(ctx + "/login.jsp")`，然后 return。
- 编译：`javac -encoding UTF-8 -cp "Tomcat/lib/servlet-api.jar;WebRoot/WEB-INF/classes" -d WebRoot/WEB-INF/classes src/com/hospital/AuthFilter.java`，并把 class 同步到 `out/production/hospital/com/hospital/`。
- 关键部署事实：Smart Tomcat 的 `conf/Catalina/localhost/hospital.xml` 用 `PreResources` 把 `D:/hospital/out/production/hospital` 挂到 `/WEB-INF/classes`，优先级高于 WebRoot 下的 classes；改 Java 类必须两处都更新，只改 WebRoot 不生效。
- 验证：编译通过；class 常量池含 `/index.jsp`、`/login.jsp`。filter 类修改需重启 Tomcat 生效（上下文未配置 reloadable），未自行停止用户运行中的进程。
