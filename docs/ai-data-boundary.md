# AI 数据边界与隔离验收

- 病历解读：POST + CSRF + 真实记录 ID。后端按登录名限制 patientname/doctor；无归属和不存在同为 404；管理员 403。本地模板解读；页面按纯文本渲染。病历草稿、质控、统计意图解析均在本地执行。
- AI 历史：患者和医生仅本人导诊；管理员可看跨账号的账号、时间和事件类型，SQL 不选正文或科室。原历史不删除、不回填。新的审计只保存固定事件描述，不保存此次输入、输出或诊断；数据库中已有敏感历史仍需按另行确认的保留策略治理。
- 导诊：双重选择，部署配置 triageExternalEnabled 默认 false，仅启用且用户本次主动允许、模型已配置时才会外发。请求只有固定系统提示、当前纯文本输入（最大 2000 字符）；服务端不转发历史、客户端角色或账户字段。自由文本可能含用户主动填写的身份信息，这不是匿名化；未审批不要在真实环境开启。triageReadTimeoutMs 默认 15000，范围 1000–60000。
- 正常流需收到上游结束标记及下游 done；无输出的失败/超时降为本地，已开始的异常结束明确中断，不将半截回复保存为完成。用户可主动重试，外发许可不沿用。浏览器默认内存会话，主动选择设备保存后才读写该账号历史；关闭保存会移除该账号的设备副本，不改服务端历史。
- 隔离结果：真实应用编译部署至独立 Tomcat、全新 MySQL 和虚构账号；模型仅限本机回环模拟。验证三角色、本人/非本人/不存在、CSRF/GET、外发字段和独立默认配置、历史审计、网络错误、超时、两段中断、浏览器重试与存储。病历解读相关模拟请求数为零。
- 未验证：正式环境、真实供应商接收与保留、医疗内容临床质量、全部浏览器/设备。本次不包含部署、数据清洗或历史删除。
